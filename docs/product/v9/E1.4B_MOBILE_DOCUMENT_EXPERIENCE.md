# E1.4B — Mobile document experience

> Status: **IMPLEMENTED_IN_PR**. Esta frente entrega código mobile e testes sobre
> a foundation E1.4A/073 já implantada. Não houve migration, produção, Storage
> write, env/secrets, Asaas, merge, deploy ou APK.

## Escopo entregue

- Viewer interno no app para PDF/imagem antes de salvar, compartilhar ou abrir
  externamente.
- Signed URL continua vindo do backend, com TTL curto; o app não persiste URL
  assinada como autoridade.
- Refresh de signed URL quando o download temporário indica expiração/falha
  compatível.
- Arquivo temporário em escopo isolado por fluxo, com nomes não previsíveis e
  limpeza de arquivos antigos.
- Scanner on-device primeiro (`cunning_document_scanner`), sem OCR.
- Review multipágina antes do upload: reorder, remove e retake de página.
- Geração local de PDF multipágina a partir das páginas aceitas.
- Upload de documentos do frete e ePOD com `client_request_id` estável por
  operação lógica; retry da mesma operação reaproveita o mesmo ID.
- Contrato v2 de documentos `outro` consumido pelo app: a UI exige nome ou
  descrição antes de enviar, e o backend permanece a autoridade final.

## Limitações reais

- `OCR_FIRST_RELEASE=false`.
- `RECIPIENT_SIGNER_UI=DEFERRED_FUTURE_B2`; a foundation de participantes não
  foi transformada em fluxo de negócio mobile nesta frente.
- Process death completo não é prometido neste primeiro release; a implementação
  cobre retry seguro enquanto a operação lógica existe no fluxo, com o mesmo
  `client_request_id`.
- Device validation fica no `MOBILE_RELEASE_TRAIN_M1`; não foi gerado APK
  manual local.
- `LEGACY_COMPROVANTES=OUT_OF_SCOPE_FOR_E14B`.
